# Capstone App Requirements — Angular SPA (Public APIs)

This document refines the Mini Project (Capstone) from the Angular Basics Handbook and specifies concrete requirements using **open/public APIs**.

> **Primary API choice:** [DummyJSON](https://dummyjson.com/) — provides auth and CRUD-like endpoints with CORS enabled.  
> **Alternatives (if needed):** JSONPlaceholder, ReqRes, The Rick and Morty API, PokéAPI, Open-Meteo.

---

## 1) Functional Scope

### 1.1 Authentication
- **API:** `POST https://dummyjson.com/auth/login`
- **Request body:** `{ username: string, password: string }` (use demo creds from docs)
- **Success:** `{ token, id, ... }`
- **Requirements:**
  - Login page (Angular Material form) with validation.
  - Store token **in memory** (service) and mirror to `localStorage` (for reload).
  - `AuthInterceptor` adds `Authorization: Bearer <token>` when present.
  - `AuthGuard` protects `/app/**` routes; `/login` is public.
  - Logout clears token and navigates to `/login`.

**Acceptance Criteria:**
- User with valid demo credentials can log in; protected routes block guests.
- Token is cleared on logout; refresh of protected pages without token redirects to `/login`.

---

### 1.2 Products List (CRUD)
- **APIs (DummyJSON):**
  - List: `GET /products?limit={n}&skip={m}`
  - Search: `GET /products/search?q={term}&limit={n}&skip={m}`
  - Details: `GET /products/{id}`
  - Create: `POST /products/add` *(CRUD is simulated by API; accept response as source of truth)*
  - Update: `PUT /products/{id}`
  - Delete: `DELETE /products/{id}`
- **UI Requirements:**
  - Page: `/app/products` with **MatTable** + **MatPaginator** + **MatSort**.
  - Columns: image (thumbnail), title, category, price, rating, stock, actions.
  - Toolbar with search (debounced), category filter (MatSelect), and “Add product” (MatDialog).
  - Details route `/app/products/:id` with a read-only view (MatCard).
  - Create/Edit uses **Reactive Form** (MatFormField, MatInput, MatSelect, MatSlider for rating, MatButton).
  - Delete asks confirmation via **MatDialog**.
- **Data Requirements:** map API shape to local model; validate:
  - `title` (required, 3–80 chars), `price` (>=0), `rating` (0–5 step 0.1), `stock` (>=0), `category` (required).

**Acceptance Criteria:**
- Table paginates server-side (limit/skip).
- Search filters results via `q` and resets pagination.
- Sort works locally (MatSort) unless you opt to implement server sort (optional).
- Create/Edit/Delete operations show **MatSnackBar** on success/error and refresh the table.
- Navigation to details works; back returns to list and keeps table state (page, search).

---

### 1.3 Theming & Layout
- **Angular Material** theming with **light/dark** toggle (MatSlideToggle).
- Persist theme preference in `localStorage`.
- Responsive layout: Sidenav collapses on `< 960px`; table becomes dense.

**Acceptance Criteria:**
- Theme switch affects all Material components.
- Layout adapts to mobile; key actions remain discoverable.

---

### 1.4 Internationalization (i18n) & Accessibility (a11y)
- **i18n:** English (default) and Ukrainian. JSON translation files; language switcher in the header (MatMenu).
- **a11y:** proper labels for inputs; focus states; ARIA for dialogs and toggles.

**Acceptance Criteria:**
- All static text is translatable; user can switch languages and language persists.
- Lighthouse **Accessibility ≥ 90** on a product list screen.

---

### 1.5 Error Handling & Empty States
- Global HTTP error interceptor: maps common codes to user-friendly messages; uses MatSnackBar.
- Empty states for list/search with a friendly illustration/message.

**Acceptance Criteria:**
- API/network errors are surfaced to the user and do not crash the app.
- Empty search/list shows appropriate UI (no raw “null/undefined”).

---

## 2) Architecture & State

- **Routing:** feature routes under `/app`, lazy-loaded. `canActivate` guard on `/app/**`.
- **State:** 
  - **Signals** for local UI state (filters, dialog state, theme).
  - **RxJS** for HTTP streams; `shareReplay` for caching details by id.
- **Change Detection:** OnPush by default; `trackBy` on repeaters.
- **Interceptors:** Auth, Error, (optional) Cache for idempotent GETs using `HttpContextToken` to opt-in.

**Acceptance Criteria:**
- No unnecessary change detection cycles; table uses `trackBy`.
- Repeated navigation to the same product id uses cached data (unless manually invalidated).

---

## 3) Performance

- Use `@defer` for optional/secondary UI (e.g., product details aside widgets).
- Route-level lazy loading; bundle splits visible in build stats.
- Images use `loading="lazy"` (if not using MatTable cell images, use `<img>` with width/height).

**Acceptance Criteria:**
- Lighthouse **Performance ≥ 90** on desktop.
- Main route initial JS chunk size is reasonable for a demo app (< 350KB gzipped target).

## Appendix A — How to Use DummyJSON API

### 1) Authentication
- **Endpoint:** `POST https://dummyjson.com/auth/login`
- **Request body example:**
```json
{
  "username": "kminchelle",
  "password": "0lelplR"
}
```
- **Response example:**
```json
{
  "id": 15,
  "username": "kminchelle",
  "email": "kminchelle@qq.com",
  "firstName": "Jeanne",
  "lastName": "Halvorson",
  "gender": "female",
  "image": "https://robohash.org/autquiaut.png?size=50x50&set=set1",
  "token": "your_jwt_token_here"
}
```
- Use the `token` in Authorization header for protected requests:
```
Authorization: Bearer your_jwt_token_here
```

### 2) Products API
- **List products (with pagination):**
```
GET https://dummyjson.com/products?limit=10&skip=0
```
- **Search products:**
```
GET https://dummyjson.com/products/search?q=phone&limit=10&skip=0
```
- **Get product by ID:**
```
GET https://dummyjson.com/products/1
```
- **Create a product:**
```
POST https://dummyjson.com/products/add
Content-Type: application/json

{
  "title": "New Product",
  "price": 199,
  "description": "Test product",
  "category": "laptops"
}
```
- **Update a product:**
```
PUT https://dummyjson.com/products/1
Content-Type: application/json

{
  "price": 250
}
```
- **Delete a product:**
```
DELETE https://dummyjson.com/products/1
```

### 3) Notes
- DummyJSON is **fake API** with simulated CRUD — changes are not persisted permanently.
- Supports CORS — works directly from Angular without a proxy.
- Some endpoints may require authentication (if enabled in future updates).
- For testing pagination: use `limit` and `skip` params, and check total count from API response.

## Appendix B — Data Shapes (for Angular Models)

> Below are **TypeScript interfaces** matching common DummyJSON responses.

### 1) Auth

```ts
export interface AuthLoginRequest {
  username: string;
  password: string;
}

export interface AuthLoginResponse {
  id: number;
  username: string;
  email: string;
  firstName: string;
  lastName: string;
  gender: 'male' | 'female' | string;
  image: string;
  token: string; // JWT-like token from DummyJSON
}
```

### 2) Product (single)

```ts
export interface Product {
  id: number;
  title: string;
  description: string;
  price: number;
  discountPercentage: number;
  rating: number; // 0..5
  stock: number;
  brand: string;
  category: string;
  thumbnail: string;
  images: string[];
}
```

### 3) Products List (paginated)

```ts
export interface ProductsListResponse {
  products: Product[];
  total: number;   // total number of products available
  skip: number;    // current offset
  limit: number;   // page size
}
```

### 4) Create/Update Requests

```ts
export interface CreateProductRequest {
  title: string;
  description?: string;
  price: number;
  discountPercentage?: number;
  rating?: number;
  stock?: number;
  brand?: string;
  category: string;
  thumbnail?: string;
  images?: string[];
}

export type UpdateProductRequest = Partial<CreateProductRequest>;
```

### 5) Error Shape (typical)

DummyJSON returns standard HTTP status codes. For demo apps, normalize errors to a minimal shape:

```ts
export interface ApiError {
  status: number;          // HTTP status code
  message: string;         // user-facing message
  details?: unknown;       // raw error payload (optional, not for UI)
}
```

> **Note:** DummyJSON is a fake API; create/update/delete are simulated. Treat returned payload as the source of truth for UI state, but don’t expect persistence across sessions.
