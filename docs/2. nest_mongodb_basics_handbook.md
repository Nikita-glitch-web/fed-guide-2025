# NestJS + MongoDB Basics Handbook — Junior Full‑Stack Developer Track

## 🎯 Goal
Master the fundamentals of **NestJS (v10+)** with **MongoDB (v6+)** to build secure, scalable REST APIs using DTO validation, Mongoose schemas, authentication/authorization, testing, and production‑grade deployment.

---

## 1. Environment Setup
**Tasks:**
- Install Node.js LTS via `fnm` or `nvm`.
- Use **yarn** as the package manager.
- Install Nest CLI: `yarn global add @nestjs/cli` (or `npm i -g @nestjs/cli`).
- Scaffold a project: `nest new api` (choose **yarn**).
- Add MongoDB stack: `yarn add @nestjs/mongoose mongoose @nestjs/config bcrypt jsonwebtoken`
- Add typings/dev tools: `yarn add -D @types/jsonwebtoken @types/bcrypt eslint prettier husky lint-staged`
- Create `.env` and `.env.example` with at least: `PORT`, `MONGODB_URI`, `JWT_SECRET`, `JWT_EXPIRES_IN`.

**Acceptance Criteria:**
- `yarn start:dev` runs the app without errors.
- `GET /health` returns `{ status: 'ok', db: 'connected' }`.

**Similar Examples:**
- NestJS + Mongoose basics — https://docs.nestjs.com/techniques/mongodb

---

## 2. Project Architecture
**Tasks:**
- Feature‑first modules: `auth`, `users`, `products`, `health`.
- Global pipes/filters/interceptors in `main.ts`:
  - `ValidationPipe({ transform: true, whitelist: true, forbidNonWhitelisted: true })`
  - Global exception filter for uniform error JSON.
  - (Optional) Logging interceptor (request id, timing).
- Config module: `@nestjs/config` with schema validation (Joi/Zod).

**Acceptance Criteria:**
- Each feature has its controller, service, DTOs, and schema.
- Invalid payloads are rejected with 400 and helpful messages.
- Error shape is standardized: `{ statusCode, message, error }`.

**Examples:**
- Global validation pipe — https://docs.nestjs.com/pipes#validation

## 3. MongoDB & Mongoose
**Tasks:**
- Connect via `MongooseModule.forRootAsync` using `MONGODB_URI`.
- Define schemas with timestamps and indexes.
- Use `.lean()` for read‑heavy queries; paginate all list endpoints.
- Implement **offset** pagination (limit+skip) or **cursor** pagination (by `_id`/`createdAt`).

**Acceptance Criteria:**
- Collections: `users`, `products` with the following:
  - **User**: `username` (unique), `email` (unique, lowercase), `passwordHash`, `roles` (`['user']|['admin']`), `createdAt`, `updatedAt`, `lastLoginAt?`.
  - **Product**: `title` (required 3–80), `description?`, `price>=0`, `rating 0..5`, `stock>=0`, `category` (indexed), `images[]`, `createdBy: ObjectId(User)`, timestamps.
- Indexes:
  - Users: unique `username`, unique `email`.
  - Products: compound `{ category: 1, price: 1 }`, text `{ title: 'text', description: 'text' }`.

**Examples:**
- Mongoose indexes — https://mongoosejs.com/docs/guide.html#indexes

## 4. DTOs & Validation
**Tasks:**
- Use `class-validator` + `class-transformer` in DTOs:
  - `CreateUserDto`, `LoginDto`.
  - `CreateProductDto`, `UpdateProductDto`, `QueryProductsDto`.
- Custom pipe `ParseMongoIdPipe` for `:id` params.

**Acceptance Criteria:**
- All controllers accept only validated DTOs.
- Invalid ObjectId yields 400 via `ParseMongoIdPipe`.

**Examples:**
- ValidationPipe — https://docs.nestjs.com/pipes#class-validator

---

## 5. Authentication & Authorization
**Tasks:**
- Local auth with username/email + password (`bcrypt`).
- Issue JWT Access Token (`JWT_EXPIRES_IN` ~ 15m). (Refresh token optional.)
- `AuthGuard` for protected routes and `RolesGuard` for RBAC.
- Store password as strong hash; never log secrets.

**Acceptance Criteria:**
- `POST /auth/login` returns `{ accessToken, user }`.
- Protected endpoints require `Authorization: Bearer <token>`.
- Role‑protected routes (e.g., create/update/delete product) only for `admin` (or resource owner).

**Examples:**
- Guards & custom decorators — https://docs.nestjs.com/guards

## 6. REST Endpoints (Products)
**Tasks:**
- Base: `/v1/products`
  - `GET /` — list with pagination, filters (`q`, `category`, `minPrice`, `maxPrice`), sort (whitelisted `price|createdAt|rating`).
  - `GET /:id` — product by id.
  - `POST /` — create (auth required).
  - `PUT /:id` — full update (admin or owner).
  - `PATCH /:id` — partial update.
  - `DELETE /:id` — soft/hard delete (define strategy).
- Text search with `$text` and score sort; fallback to case‑insensitive regex if `q` < 3 chars.

**Acceptance Criteria:**
- Response for list includes `{ items, total, page, limit }` (or cursor token).
- CRUD returns saved documents (after write).
- Errors are consistent and safe for clients (no stack traces in production).

**Examples:**
- Controllers & routing — https://docs.nestjs.com/controllers

## 7. Performance & Data Access
**Tasks:**
- Use `.lean()` on read endpoints.
- Projections to limit fields.
- Handle array updates with atomic operators (`$addToSet`, `$pull`, `$inc`, `arrayFilters`).
- Implement optimistic concurrency (`__v`) or conditional updates by `updatedAt`.
- Benchmark critical queries with `.explain('executionStats')` in dev.

**Acceptance Criteria:**
- Paginated list returns < 200ms on a warmed local DB (seeded ~10k docs).
- No unbounded `find()`; all lists are paginated.

**Examples:**
- Mongoose lean — https://mongoosejs.com/docs/tutorials/lean.html

- Structured logs include level, timestamp, requestId, path, status.
- Swagger documents all public endpoints and DTOs.

## 9. Testing
**Tasks:**
- **Unit**: services, guards, pipes (mock Mongoose models).
- **Integration/E2E**: `@nestjs/testing` + `supertest` against real Mongo (docker) or `mongodb-memory-server`.
- Scenarios: login success/failure; products list filters; CRUD happy path; RBAC denial; invalid DTO.

**Acceptance Criteria:**
- `yarn test` passes; at least 6 unit and 4 e2e tests.
- Coverage on services/controllers ≥ 60% for critical modules.

**Examples:**
- Testing — https://docs.nestjs.com/fundamentals/testing

## 10. Security Checklist
**Tasks:**
- Helmet, CORS (allowlist), rate limit (e.g., per IP route).
- Hide stack traces in production, use safe error messages.
- Validate and sanitize all inputs (DTOs).
- Don’t log PII or tokens; redact sensitive fields in logs.

**Acceptance Criteria:**
- Security middleware enabled in main app.
- Basic OWASP concerns addressed (XSS via templating not relevant for API; protect against NoSQL injection by whitelisting fields).

**Examples:**
- Security — https://docs.nestjs.com/security/helmet

## 11. Deployment
**Tasks:**
- Add Dockerfile (multi‑stage, alpine, non‑root) and `docker-compose.yml` with `mongodb` service.
- Healthcheck in Docker and app endpoint.
- Compare hosting options and document pros/cons:
  - **MongoDB Atlas** (managed) vs **self‑hosted Mongo** (Docker on VPS).
  - **Node hosting**: Render/Fly.io/Cloud Run vs **VPS with Docker**.
- Configure environment via `.env`/secrets; never commit secrets.
- Enable index sync on startup behind env flag (`SYNC_INDEXES=true`).

**Acceptance Criteria:**
- App runs with `docker compose up -d` locally.
- Public URL for API is available (if you deploy).
- Short comparison doc (1–2 paragraphs) included in `/docs/deployment.md`.

**Examples:**
- Nest deployment — https://docs.nestjs.com/cli/usages#production-build
